# OpenMontage Studio

视频全流程流水线工作台插件（HanaAgent / OpenHanako）。

把"一个视频项目的生命周期"拆成四样东西：**不可逆的工序链、认知分工、工件流转、验收门**。插件把编、导、制三个工位放进同一块面板，工序状态机驱动推进，工件登记入库，验收两级（必修/建议），执行状态实时回流。

## 特性

- **三工位同屏**：编（剧本/分镜）、导（需求/审片/验收）、制（素材/剪辑/合成/交付）各有一个独立会话 Tab，消息互不串扰
- **Pipeline 驱动**：工序泳道数量随所选管线动态生成；不配置外部仓库时使用内置默认工序（需求→剧本→分镜→素材→剪辑→合成→审片→交付）
- **工件库**：工序产出登记入库，按阶段/类型/状态分组，文本、图片、视频可直接预览
- **两级验收**：验收意见分"必修（不过即回退）"与"建议（放行留档）"；回退可跨级，工件自动升版；同一阶段连续回退 2 次自动升级等待主人裁决
- **执行面板**：制作工位通过 `task_report` 工具汇报进度，实时呈现在面板上
- **文件导入 & 本地工作台**：页面一键导入本地文件/文件夹到项目工作台（自动登记为工件并可直接预览）；项目可绑定本地文件夹作为工作台根目录，素材自由进出
- **投递到桌面端工作台**：工件库每一项（或一键全部）可投递到 Hana 桌面端工作台，视频/图片/PDF 等直接在桌面端预览
- **一键准备工位**：新环境装完点「准备工位」即可，已存在的 Agent 直接复用，缺失的自动创建为插件私有 Agent
- **零构建**：direct 模板（vanilla JS + 服务端注入），无 npm 依赖，安装即用

## 安装

把整个 `openmontage-studio` 目录放入 Hana 的插件目录（如 `~/.hanako/plugins/`），重启 Hana 后启用。要求 Hana 版本 ≥ 0.171.3。

## 首次使用准备（新用户必读）

插件需要三个**工位 Agent**：编、导、制，每个对应你 Hana 环境中的一个 Agent 实例。工位会话绑定到这些 Agent 上，没有它们插件无法开工。

### 方式一：一键准备（推荐）

打开视频工坊页面，点击右上角**「准备工位」**按钮。插件会自动检查三个工位 Agent：已存在的直接复用，缺失的自动创建为插件私有 Agent（不会出现在你的主 Agent 列表，不影响日常使用）。

### 方式二：手动配置

在 Hana 的 Agent 管理里创建（或选择已有的）三个 Agent，然后在插件设置里填入对应 id：

| 角色 | 建议 id | 职责 |
|------|---------|------|
| 编 | `bianju` | 剧本、分镜等创意文本工序 |
| 导 | `daoyan` | 需求梳理、审片、验收决策 |
| 制 | `zhizuo` | 素材、剪辑、合成、交付 |

插件设置 → `agentScript`（编）、`agentDirector`（导）、`agentMaker`（制）三项，填入你环境里真实存在的 Agent id。id 可以任意命名，只要与设置一致。

### 验证

打开视频工坊，向任一工位发一条消息。收到回复即就绪。若失败，页面会直接提示当前配置的 Agent 与排查方向。

## 配置

插件设置里可配五项（留空/缺省即用默认值）：

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `agentScript` | 编剧工位绑定的 agent id | `bianju` |
| `agentDirector` | 导演工位绑定的 agent id | `daoyan` |
| `agentMaker` | 制作工位绑定的 agent id | `zhizuo` |
| `openmontageRepoPath` | OpenMontage-repo 绝对路径（可选） | 空（使用内置默认工序） |
| `deskDeliverDir` | 投递到桌面端工作台的目标目录（可选） | 空（自动探测，受限时需手动配置） |

> 三个工位 agent 需在你的 Hana 环境里真实存在；修改配置后新建的项目会使用新的工位映射。

`openmontageRepoPath` 指向包含 `pipeline_defs/*.yaml` 的仓库目录。若留空，项目使用内置默认工序，插件仍完整可用。

## 使用

1. 打开"视频工坊"页面，点击**新建项目**，填标题/需求/管线（可填 `workDir` 绑定本地文件夹作为工作台）
2. 项目创建后自动初始化工序状态与资产目录骨架
3. **导入素材**：点「导入文件」选择本地文件，自动复制进工作台并登记为工件，视频/图片可即时预览
3. 每个工位 Tab 内与对应 agent 对话，交代本工序需求
4. 工位完成后调用 `stage_report` 申报"待验"
5. 验收人调用 `stage_approve`（通过并推进）或 `stage_reject`（退回指定阶段）
6. 制作工位在工序节点调用 `task_report` 汇报执行状态，面板实时更新

### 提供给 agent 的工具

| 工具 | 用途 |
|------|------|
| `project_create` / `project_list` / `project_get` / `project_update` / `project_delete` | 项目管理（project_create 支持 workDir 本地工作台） |
| `station_setup` | 一键准备工位 Agent（存在复用，缺失自动创建） |
| `file_import` | 导入本地文件到项目工作台并登记为工件 |
| `stage_report` / `stage_approve` / `stage_reject` | 工序状态机推进 |
| `artifact_register` | 工件登记入库（文件实体由工位写入项目目录） |
| `task_report` | 执行任务状态回流（进度/日志/产出路径） |

## 架构

业务逻辑在 `lib/`（纯函数 + JSON 存储），路由 `routes/` 只做 HTTP 适配，工具 `tools/` 是给 agent 的薄壳。项目元数据存插件 dataDir，工件文件实体存工作区项目目录，两者分离。

详细设计（状态机规则、实体模型、风险登记册、实施记录）见 [DESIGN.md](DESIGN.md)。

## 安全边界

- 插件只读写自身 dataDir 与项目 workDir；工件读取拒绝目录穿越与项目外绝对路径
- 可选数据源 OpenMontage-repo（AGPL-3.0）仅作静态读取；**发布该仓库前务必清理 `.env`**（其 gitignore 已排除 `.env`，但直接打包目录时极易误带，内含大量第三方 API 密钥）
- **已知限制**：投递到工作台的目标目录自动探测依赖 Hana 本地凭证，受限环境可能失败；失败时请在插件设置里手动配置 `deskDeliverDir`。另外建议把项目工作台直接绑定到 Hana 工作台可见目录，则无需投递
